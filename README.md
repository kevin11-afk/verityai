# VerityAI

**Multimodal AI-Generated Content Detection with Evidence-Grounded RAG**

*"Investigate the media. Examine the evidence."*

VerityAI is an educational screening tool that combines a real pretrained
computer-vision detector with Retrieval-Augmented Generation (RAG) over
AI-media-forensics research. It estimates whether an uploaded image (or,
experimentally, a short video) may be AI-generated, and backs every result
with cited research evidence and explicit limitations — never a free-form
guess from a language model.

**Everything here runs for ₹0 / $0.** No paid APIs, no paid hosting, no
credit card, no billing account. See "Cost & licensing" below for exactly
which free services and licenses this relies on.

## Features

- **Image analysis**: drag-and-drop upload, live preview, real detector
  inference (no random/hardcoded results), raw model scores, a fixed and
  disclosed decision policy, research-backed explanation with citations,
  downloadable JSON/Markdown report.
- **Video analysis (experimental)**: duration/size validation, evenly-
  spaced frame sampling with OpenCV, the *same* image detector run per
  frame, a disclosed mean-aggregation method — explicitly not a temporal
  deepfake detector.
- **Research Assistant**: ask free-text questions about AI-media
  detection; answers are retrieved passages with page-level citations, or
  an explicit "insufficient evidence" notice — never an uncited guess.
- **Evaluation Dashboard**: real precision/recall/F1/ROC-AUC/latency for
  the detector and real Recall@K/MRR/citation-coverage for retrieval, when
  labeled data is supplied — otherwise shows "Not evaluated" honestly.
- **About / Methodology**: full architecture, model cards, decision
  policy, ethical-use notes, limitations, and privacy information.

## Architecture

```
Upload (image/video)
    │
    ▼
Validation (extension + magic-byte signature + size + dimension/duration)
    │
    ▼
Real detector inference (Nahrawy/AIorNot, Swin-Tiny, CPU)
    │                                   │
    ▼ (category + raw scores)          ▼ (used to build a retrieval query)
Decision policy (fixed thresholds)   Hybrid RAG retrieval
                                        │
                      BM25 keyword search ─┐
                      ChromaDB vector search├─ Reciprocal Rank Fusion
                                        │
                        Deterministic template-based explanation
                        (detector output vs. research findings kept
                         strictly separate; every claim cited)
                                        │
                                        ▼
                    Report (on-screen + JSON/Markdown download)
```

No LLM is used anywhere — explanations are generated by deterministic
Python templates in `src/rag/generation.py`, not by prompting a model.

## Model details

| | Detector | Embeddings |
|---|---|---|
| Model | `Nahrawy/AIorNot` | `sentence-transformers/all-MiniLM-L6-v2` |
| Base architecture | Swin-Tiny (swin-tiny-patch4-window7-224) | MiniLM |
| Parameters | ~28M | ~22.7M |
| License | Apache-2.0 | Apache-2.0 |
| Training data | "aiornot" competition dataset (~62k images, Real/AI) | general sentence-similarity corpora |

Three alternative detectors were researched and compared before this
choice — see `knowledge_base/04_detector_model_cards.md` for the full
comparison (license, size, training data, and why each was or wasn't
selected). The short version: Apache-2.0 licensing and the smallest
parameter count (best fit for an 8GB-RAM laptop and Streamlit Community
Cloud's limited-RAM free tier) decided it.

**Decision policy** (fixed, documented, not tuned on this project's own
data — see `src/config.py`):
- `P(AI) ≥ 0.65` → **AI-generated suspected**
- `P(Real) ≥ 0.65` → **Real or non-synthetic suspected**
- otherwise → **Inconclusive**

A raw softmax score is always reported as exactly that — never implied to
be a calibrated probability of authenticity.

## Installation

Requires **Python 3.11** (tested on 3.11.15, macOS arm64; 3.10 should work; 3.12+ is untested
with the pinned `torch`/`chromadb`/`numpy` versions). Install 3.11 free with
`uv python install 3.11` or `brew install python@3.11`.

```bash
git clone <your-repo-url> verityai
cd verityai

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# Install the CPU-only PyTorch build FIRST — this keeps install size and
# RAM usage small. Installing torch via requirements.txt directly can pull
# a much larger CUDA build on some platforms.
pip install torch==2.4.1 --index-url https://download.pytorch.org/whl/cpu

pip install -r requirements.txt
```

The detector and embedding models (~130MB combined) download automatically
from Hugging Face Hub the first time they're used, and are cached locally
afterward (`~/.cache/huggingface` by default) — no action needed, but the
first run needs internet access.

## Running the app locally

```bash
# 1. Build the knowledge-base index (one-time; re-run after adding documents)
python scripts/ingest_documents.py

# 2. Launch the app
streamlit run app.py
```

Open the URL Streamlit prints (typically `http://localhost:8501`).

## Knowledge-base ingestion

```bash
python scripts/ingest_documents.py            # index new/changed documents
python scripts/ingest_documents.py --rebuild   # drop and rebuild the whole index
python scripts/ingest_documents.py --inspect   # list what's currently in knowledge_base/
python scripts/ingest_documents.py --debug "your question here"  # test retrieval directly
```

See `knowledge_base/README.md` for how to add your own PDF/TXT/MD sources
(including how to attach a citable source URL via a `.url` sidecar file).

## Testing

```bash
pytest tests/ -v
```

Covers: file-type/size/dimension/signature validation, path-traversal
protection, the detector's decision-policy logic (with mocked model
outputs — **mocks are used only in these unit tests, never in the
production app**), chunking and citation-metadata preservation, BM25 and
vector and hybrid (RRF) retrieval, missing-evidence handling, and report
generation/serialization.

> **Status:** the full suite (42 tests, including retrieval against real
> ChromaDB and BM25) passes on Python 3.11 / macOS arm64 from a clean
> install of `requirements.txt`. Mocks are used only for the model in unit
> tests; see `TRANSFER.md` for what was and wasn't verified end to end.

## Evaluation instructions

A first measurement (200 images, AUC ≈ 0.85) and a comparison with three
other detectors are in `EVALUATION.md`, with reproduction commands.

`scripts/evaluate.py` prints **real, computed metrics only** — it prints
"Not evaluated" for anything it has no labeled data for, rather than a
placeholder number.

**Detector evaluation** — populate:
```
data/eval/images/real/*.jpg
data/eval/images/ai/*.jpg
```
A free, clearly licensed option: [CIFAKE](https://www.kaggle.com/datasets/birdy654/cifake-real-and-ai-generated-synthetic-images)
(Bird & Lotfi, 2023) on Kaggle — but read
`knowledge_base/02_generalization_and_dataset_bias.md` first: CIFAKE's
32x32-upsampled images are a known-biased benchmark, so treat its numbers
as a sanity check of the pipeline, not a claim about real-world accuracy.
For a more realistic test, hand-label a few dozen of your own real photos
and AI-generated images (keep this set separate from anything used to pick
thresholds — see `knowledge_base/06_evaluation_methodology.md` for why).

**RAG evaluation** — populate `data/eval/rag_eval.jsonl`:
```
{"question": "...", "relevant_chunk_ids": ["doc.pdf:p3:0:abc123..."]}
```
Get real chunk IDs with `python scripts/ingest_documents.py --debug "your question"`.

Then run:
```bash
python scripts/evaluate.py
```
Or open the **Evaluation Dashboard** page in the app and click "Run
evaluation now."

## Deployment (Streamlit Community Cloud)

**Status: not yet deployed.** Everything below the line "Verified locally"
was run on a Mac; the Cloud steps themselves have never been executed.

Free-tier facts (per the Streamlit docs when last checked, 2026-10-18; they
can change without notice, so re-check): free, GitHub sign-in, no credit
card, per-app memory between **690 MB and 2.7 GB** (older sources say 1 GB),
apps sleep after inactivity. Cloud installs `requirements.txt` with `uv`.

**Verified locally (macOS arm64, Python 3.11, ₹0)**
- `uv pip compile requirements.txt --python-platform x86_64-manylinux_2_28
  --python-version 3.11` resolves for Linux, picks `torch==2.4.1+cpu`, and
  pulls no CUDA/nvidia packages.
- The running app, after image analysis, research retrieval and video
  analysis in one process: ~650 MB RSS (~390 MB peak footprint).
  `device="cpu"` is forced for embeddings so this matches a GPU-less host.
  **Linux memory was not measured.** If Cloud enforces the 690 MB floor the
  headroom is thin; at the 2.7 GB ceiling it is comfortable.
- First start downloads two models (~200 MB) and builds the index (~30 s).

**Steps**
1. Create a free GitHub account if needed, create a **public** repo, then
   from this folder:
   ```bash
   git branch -M main
   git remote add origin https://github.com/<you>/verityai.git
   git push -u origin main        # push the branch you want to deploy
   ```
   (Confirm `git ls-files` shows no `.venv/`, `chroma_db/`, `data/eval*`.)
2. Go to [share.streamlit.io](https://share.streamlit.io), sign in with
   GitHub, click **Create app**, and pick the repo, branch `main`, main file
   `app.py`.
3. Under **Advanced settings** choose **Python 3.11**. Do not add secrets;
   none are needed.
4. Deploy and watch the build log. Confirm that torch installs as `+cpu`
   and that no `nvidia-*` packages appear. If the build fails or the app is
   restarted for memory, check **Manage app → logs**.
5. **Test the public URL before calling it deployed**: upload a real image
   (expect a prediction, scores and cited passages), download both reports,
   ask an on-topic and an off-topic question in Research Assistant, and try
   a short video.
6. If memory is exceeded, the options are to remove the Video page (delete
   `pages/2_Video_Analysis.py`), or switch the detector to ONNX Runtime
   (see Future improvements). There is no setting to disable video.

## Privacy and security notes

- Uploads are validated by extension **and** file signature (magic
  bytes), not filename alone.
- Temp files are written with random UUID names under `data/tmp/`, never
  derived from the user's filename — this is what prevents path
  traversal. Files are deleted immediately after analysis.
- No uploaded media, filename, or result is sent to any external API. The
  only outbound network calls are the one-time Hugging Face Hub model
  downloads (cached afterward).
- `showErrorDetails = false` is set in `.streamlit/config.toml` so a
  public deployment never leaks a stack trace or local filesystem path to
  a visitor.
- Retrieved document text and uploaded files are treated as untrusted
  data throughout — never executed, never interpolated into a prompt as
  anything other than plain quoted text (there is no LLM prompt at all,
  which removes an entire class of prompt-injection risk from documents).

## Known limitations

- **Detector accuracy is moderate** (ROC-AUC ≈ 0.85, ~21% of real photos
  flagged as AI on a 200-image sample; see `EVALUATION.md`).
- The relevance gate (`MAX_BEST_VECTOR_DISTANCE`, 0.65) was calibrated on
  18 queries against this small knowledge base; re-check it if you add documents.
- The image detector is a single pretrained binary classifier, not an
  ensemble, and has not been independently re-evaluated by this project
  on a fresh out-of-distribution test set — see the Evaluation Dashboard
  for real numbers (or "Not evaluated" if you haven't supplied data yet).
- Trained on data predating 2024; newer generators are effectively
  "unseen" to it (see `knowledge_base/02_generalization_and_dataset_bias.md`).
- Video analysis is frame-level only, not a validated temporal detector.
- The bundled knowledge base is a small, hand-curated starter set (6
  documents, ~8 citations) — it will say "insufficient evidence" rather
  than guess on anything outside it.
- No face-specific or deepfake-specific model is bundled; the detector is
  a general real-vs-AI image classifier.
- Streamlit Community Cloud's memory limit (690 MB–2.7 GB per the docs) may be tight for this stack — see
  "Deployment" above.

## Future improvements

- Export the detector to ONNX Runtime to cut RAM/latency on the hosted
  free tier (see `knowledge_base` for why this wasn't the starting point:
  "do not train/convert anything beyond what's needed for a working,
  honest v1").
- Add a second, independently-trained detector and report both results
  (closer to an ensemble) rather than relying on a single model.
- Add C2PA Content-Credentials verification as a complementary, non-
  pixel-based signal (see `knowledge_base/05_content_provenance_c2pa.md`).
- Grow the knowledge base with more sources and a periodic re-ingestion
  job.
- Optional local small LLM for more natural-language (but still
  citation-constrained) explanations — explicitly optional, never
  required for the core app to work, per the project's own requirements.
